## 1. 产品定位与决策边界

### 1.1 一句话定位

**给打工人在等待 Codex 等工具出结果时，打开本地终端玩几回合、随时回到工作的轻量修仙游戏。**

终端不是过渡用的调试壳，而是本轮产品的主要使用入口。准确称谓是 TUI（终端文本界面）：用字符、色块、边框、菜单和键盘输入形成游戏画面，不以浏览器或原生图形窗口为交付前提。

它追求的是“碎片化游玩、长期角色积累”，不是一次启动就完成整段修仙生涯，也不是实时在线挂机。

### 1.2 已确认与未确认事项

### 1.3 典型使用场景

1. 用户在一个终端会话里运行工作任务。
2. 在另一个标签页、分屏或终端窗口启动游戏；不占用工作进程的标准输入输出。
3. 自动恢复上次进度，用一句“上次停在……”帮助回忆。
4. 做一到数个选择，看见明确收益、代价或剧情进展。
5. 工作需要注意时立即退出，下一次从同一事件或战斗轮继续。

无需读取 Codex 日志、监控工作进程、接管凭据或与其集成。“等 Codex”是使用背景，不是外部接口需求。

## 2. 体验目标、范围与反目标

### 2.1 建议体验目标

以下是要验证的目标，不是已取得的性能成绩：

- 已安装、无网络时，一条命令进入游戏；参考设备上新进程启动至可操作目标P95不超过2秒，首次启动单独记录。
- 普通选择机械结算目标P95不超过50ms，含落盘和渲染的可见结果目标P95不超过200ms；不等待AI才允许继续。测量方法见开发方案第15节。
- 一次普通交互预期约 5～30 秒，一次短游玩可在 1～5 分钟内形成小段进展。以实测为准，不规定玩家必须快速阅读。
- 每次有效行动持久化；战斗、渡劫、未决选择均可中断和恢复。
- 没有输入时游戏时间暂停；用户去开会、切窗口或关游戏不会损失寿元。
- 默认静音，无终端响铃、无抢焦点通知；空闲时事件驱动等待，不高频刷新。
- 核心流程用键盘完成；窄终端可玩，信息多时分页，不要求滚动寻找选项。
- 不要求用户更换字体或安装开发工具才可开始；提供朴素兼容模式。

### 2.2 核心循环

恢复进度 → 查看一个事件和关键状态 → 选择行动 → 校验与必要确认 → 确定性结算 → 安全落盘 → 显示变化和下一选择。

“简单”首先指操作、进入成本与注意力负担，不意味着删去修仙世界的成长和失败。

### 2.3 版本范围

| 版本 | 内容 | 发布意义 |
|---|---|---|
| M0 | 定位/规则冻结、真实终端验证、技术与存档契约 | 还不是游戏 |
| M1 | 创角、修炼、疗伤、基础交易与任务、少量战斗、炼气至筑基初期、死亡和恢复 | **可独立交付的离线终端小游戏** |
| M2 | 可关闭的 AI 意图理解与叙事增强 | 可选增强，不阻塞 M1 发布 |
| M3 | 关系、生活技艺、洞府、NPC 月度生态、授权闭关、构筑 | 验证短时体验后逐批增加 |
| M4 | 十境四阶、完整世界/道途/结局与长期平衡 | 长线版本，不承诺首版全部覆盖 |

M1只交付完整人道筑基路线；地道、天道及其他高境内容后续扩展。本决定已在ADR-001冻结，禁止在首版菜单中显示为可用。

### 2.4 本版不做

- 浏览器前端、移动端响应式、云账户、云存档、多人联机、付费商城、公网部署。
- 强制登录、强制联网、内置本地大模型、首次启动临时下载运行环境。
- LaTeX 运行时和 LaTeX 导出作为首版交付要求。
- 实时动作、强制倒计时、签到惩罚、按现实时间增长的债务和寿元消耗。
- 自动识别工作软件、修改工作终端日志、伪装系统进程或干预办公环境。
- 用立绘、视频或复杂图形效果作为画面成立的条件。

## 3. 对旧讨论和已有原型的准确定位

已有文件 `prototypes/panel-renderer-tui/render_demo.py` 和同目录 `demo.html`、`demo.txt`、`demo.ansi.txt` 是**静态面板渲染试验**，不是已经可玩的小游戏。新增的 `tools/task02-terminal-probe/interactive_probe.py` 是独立交互探针，也不含游戏规则或存档。

可复用：示例配色、状态卡内容、字符网格思路、多宽度布局试验。

交互探针已实现键盘事件循环、尺寸变化重排、场景分页、四档颜色输出（真彩/256色/16色/无色，含真实降级）和退出清理；80×24、64×20、48×16已有布局自动化检查，当前Windows PowerShell PTY也有一次按键/正常退出记录。三项原型修正项已修复：转义序列载荷不再泄漏、布局溢出改为显式失败、`compat`成为真正的色码回退。Windows Terminal、VS Code、传统conhost、实际拖动缩放、Ctrl+C/EOF恢复和具体字体的兼容矩阵仍未完成。游戏结算、暂停恢复、持久化和可执行发行包尚未实现。详细记录见[TASK-02验证记录](TASK-02-终端交互验证记录.md)。

必须纠正以下结论：

1. 网格按预设字宽计算通过，不等于实际终端无错位；固定网格仍会截断内容。原型的 `bad` 检查结果未被用于阻止成功文案，不能把文案当作强验收证据。
2. “77 列不折行”只来自当前样例及测量逻辑，不是产品通用最小宽度。长中文无空格、组合字符、缩窗、宽字符覆盖和高度分页仍待测。
3. 原型叫 `compat` 的分支改变了配色和字符，但 `to_ansi()` 仍输出 24 位颜色序列，**尚非真正的 ANSI 16 色回退**。
4. HTML 只是便于看样式的模拟，不是 TUI 真机截图；不能证明输入、退出和字体兼容。
5. 终端可否处理鼠标取决于终端与实现，并非一律不支持；本项目仅决定键盘优先。
6. TypeScript 不等于必须交付 React/Vite，也不等于一定要求玩家自行安装 Node。应比较具体发行产物；Python 脚本也不是无需 Python 运行时的独立程序。
7. 终端方案替换 LaTeX 主通道是产品规则变更，不是 1:1 复刻。字符宽度、字体、色彩、输入和终端恢复验证并不会消失。
8. 现实时间推进不属于本次需求。默认不采用，避免和随时离开的定位冲突。

旧原型包含的“五月/春”等演示文案和境界压制表述不能直接当成新引擎的规则数据。

## 4. TUI 画面与输入设计

### 4.1 单屏信息结构

默认界面只展示当前场景，而非将组件库的所有面板一起输出：

1. 标题、地点、游戏年月。
2. 紧凑角色条：境界、气血、灵力、修为、剩余寿元、灵石。
3. 当前事件：1～3 句，必要风险单独一行。
4. 2～4 个选择，使用数字或字母键。
5. 最近行动变化摘要与保存状态。
6. 常用操作：详情、背包、帮助、退出。

完整六维、宗门职位、关系、功德业力等放在详情页；不能每回合强制铺开整张大表。风险、可选操作和存档失败提示不得被折叠隐藏。

### 4.2 终端尺寸策略

| 建议测试尺寸 | 布局策略 |
|---|---|
| 80×24 及以上 | 标准紧凑面板；可展开详情 |
| 64×20 | 次要信息折行，菜单分页 |
| 48×16 | 单栏、短标签、状态分组，剧情分页但同一事件不重复结算 |
| 小于声明的最小支持尺寸 | 提示扩大窗口或切换朴素模式，禁止静默截断关键选择 |

这些是验收用例，不是已实测支持承诺。宽和高都要响应；“只有一个事件面板”不代表一定能装进一屏。

缩放后只重排视图，不推进月份、不重抽事件。过长姓名、连续中文、宽字符、组合字符和粘贴文本必须有边界处理。

### 4.3 色彩与兼容档位

- 真彩档：继承青玉、朱砂、玄紫、鎏金等语义；正文和背景以可读性为先。
- 基础色档：真正使用 ANSI 基础前景/背景色码；不以换成另一组 RGB 值冒充降级。
- 无色档：ASCII 框线和文本进度条；危险明确写“危险”，不只变颜色。
- 提供深浅主题或跟随配置；宣纸风作为选项，不强制用白色大块覆盖所有终端背景。
- 不使用 emoji；不能保证所有 Unicode 字符在所有终端宽度相同。
- 非 TTY、输出重定向和不支持控制序列时，进入明确的朴素输出模式或说明不支持交互，不把控制码写满日志。
- 用户输入、存档、内容包和 AI 文本都过滤终端控制序列，尤其 ESC、OSC、响铃等；不得允许文本触发剪贴板操作或伪造提示。

### 4.4 操作约定（待实测冻结）

- 数字/字母：选择；方向键/回车可作为增强支持。
- `Esc`：取消当前非提交操作或返回；不暗中替玩家选默认项。
- `q`：退出并保留最近一致状态；`Ctrl+C` 走正常终端恢复路径。
- 重大决定显式确认；普通修炼不层层弹确认。
- M1 支持菜单与有限命令；自由中文输入属于 M2 可选增强，不能阻塞基本操作。
- EOF、安全退出、异常和中断都需恢复光标、输入回显、终端颜色及所使用的屏幕模式。
- 对强制杀进程或断电不承诺执行退出钩子，只保证已提交进度可恢复。

## 5. 时间、暂停与存档原则

### 5.1 三种计数

- `interactionSeq`：已接受且提交成功的领域动作序号；查询、空输入和重复提交不增加。
- `worldMonth`：已完成结算的世界月。
- `combatRound`：战斗轮次。

查看状态、帮助、危险确认、创角和战斗招式不自动增加世界月。每个命令显式声明时间成本。

开局建议为天玄历 387 年一月；1～3 月春、4～6 月夏、7～9 月秋、10～12 月冬。年龄、寿元内部统一整数月。

### 5.2 不输入就暂停

现实时间不自动映射游戏时间。切出窗口、关闭游戏、电脑休眠、系统时间变化都不会推进世界月。NPC、种植和债务亦只跟随游戏月份。

世界真实残酷体现在玩家选择的后果，不体现在现实工作占用了玩家注意力。

### 5.3 授权闭关

“闭关 X 月/年”是一次显式授权的**逐月模拟计划**，不是后台现实计时：

- 月份逐次结算，记录 `requestedMonths`、`remainingMonths`、`stopReason`。
- 遇到寿尽边界、瓶颈、重大决定、战斗、故人告急时停止。
- 长计算分块，可取消；取消后的未执行月份不再继续增长。
- 未完成计划随存档保存，恢复时询问继续，不自动补跑。
- 平淡月合并摘要，但机械事件逐月可审计。

离线现实推进若未来探索，必须另立模式、明确倍率、上限和中断规则，默认关闭，不作为本版任务的隐含范围。

### 5.4 保存与继续

自动恢复点、命名手动存档和高风险前检查点分开。每次有效选择、每个已提交战斗轮以及待决候选产生后落盘。

- 恢复必须包含战斗、待选事件、随机状态和未完成月行动。
- 正常退出不损失已提交状态；提交中被杀进程，只能恢复旧完整状态或新完整状态。
- 存档失败不得显示“已保存”，不得继续接受会扩大损失的写入行动。
- 普通模式死亡先显示原因，再提供明显的“读取最近检查点/重开”；无合法存档时说明原因，不能承诺永远有档可读。
- 读档形成新分支，死亡记录保留；不把读档写成角色在世界中复活。
- 铁人模式不进入 M1。

### 6.1 创角与成长

- 保留姓名、道号、自定义性别、外观、十种出身、六种道途、灵根、体质、天赋和六维。
- 两步创角，第一页署名“作者：雾见川”；提供可调整的合法预设，减少开始成本。
- 原稿年龄16～60；不足18岁只开放非性内容。任何亲密内容要求双方明确成年、自愿，非露骨淡出；年龄不明或少年外形角色不开放性内容或双修奖励。
- 不以性别锁定关系；友谊、师徒、结义、宿敌可长期维持，不强制转恋爱。
- 天赋默认5点；各正面天赋暂定1点，体弱多病返还2点、每种一次；均是待平衡补值。
- 妖族出身先记录意向，资质分配后用未计妖族加成的仙缘判定；失败允许改选，但不能靠刷新反复抽。

### 6.2 修炼、战斗与失败

保留修炼、突破、寿元压力、境界压制、资源取舍和失败后果。普通进展尽量一次选择就有反馈，突破与战斗可以多节点，但每节点能保存退出。

伤势区间：0进入后果判定；(0,33%)垂死；[33%,66%)重伤；[66%,100%)轻伤；100%健康。临时伤势只影响有效属性，不损毁永久基础属性。

气血0的后果来自遭遇预置规则：切磋停止、被俘、已存在的救援条件或死亡。不能临时编造救命。危险选择前提示，接受风险后真实结算。

### 6.3 世界、内容和长期乐趣

- M1 场景：青岳洞府、青云宗、天机坊市、低危历练点；至少3名具名NPC、12个事件节点、问道飞升/守护所爱两条早期目标。
- 两条主线都须有散修可达路径，不能强制入宗才能玩下去。
- 宗门、六技艺、洞府、九悟道分支、秘境和战宠分批增加；未开发入口标记未开放或隐藏。
- NPC 变化由游戏月结算；玩家不玩时世界也暂停，玩家授权闭关时才出现岁月流逝。
- 区域仅采用原稿架空地名、场景列表与连通关系，不使用现实坐标或真实地理边界。
- 内容优先增加差异化选择和有结果的短事件，不以长篇叙事或无意义重复提高时长。

## 7. 数值基线与平衡方法

### 7.1 修炼公式

月增量 = 境界基数 × (1 + 0.05 × 有效资质) × 灵根倍率 × 主功法品级倍率 × 环境倍率 × 心境倍率 × 行动倍率 × (1 + 同组独立加成和) × 额外伤势修正。

伤势降低有效资质与直接降低修炼效率是不同效果，必须具名；同一个惩罚不重复应用。对应系变异灵根另乘1.2。

- 灵根：天2.0、地1.6、真1.3、伪1.0、变异1.8。
- 功法：黄1.0、玄1.3、地1.7、天2.2、仙3.0。
- 环境：贫瘠0.6、普通1.0、浓郁1.5、福地2.0、洞天2.5。
- 心境：高于阈值1.2、等于1.0、低于0.5；阈值配置化。
- 普通修炼1、闭关2；主修品级不与相同含义的词条重复叠加。
- 定点数保留至少万分位累计，显示时才舍入。

基准例：炼气、资质10、真灵根、黄阶、普通环境、心境达标，无其他词条，普通月增19.5，闭关39；先天道体独立+50%后普通29.25。

### 7.2 境界表

下表寿元来自原稿；结晶/具灵基数与所有未明确的修为阈值是旧方案延续的试算，不是最终平衡。

| 境界 | 寿元上限/年 | 月基数 | 每小阶修为阈值（试算） |
|---|---:|---:|---:|
| 炼气 | 100 | 10 | 100 |
| 筑基 | 200 | 9 | 300 |
| 结晶 | 300 | 8.5（补） | 600 |
| 金丹 | 500 | 8 | 900 |
| 具灵 | 800 | 7.5（补） | 1200 |
| 元婴 | 1200 | 7 | 1800 |
| 化神 | 2000 | 6 | 3000 |
| 悟道 | 5000 | 5 | 6000 |
| 羽化 | 10000 | 4 | 12000（变更候选） |
| 登仙 | 50000 | 3 | 24000（变更候选） |

每境初/中/后/圆满四阶。羽化/登仙阈值超过原稿“数千点”量级，尚未批准，不得作为高境界正式发行参数。小数基数本身不是错误，重点是来源、可解释性与节奏验证。

### 7.3 突破与战斗试算

- 小突破：`clamp(70 + 2 × (悟性 - 10) + 加成 - 瓶颈惩罚, 5, 95)%`；失败回本阶阈值70%。
- 成功升阶或升境后，新阶段修为从0开始；达到阈值时截断，超额修为不跨阶结转。界面提前提示满额与预计溢出，不自动替玩家突破。
- 炼气至筑基启动率候选：人道95%、地道85%、天道70%；M1只启用被冻结的道路。后续雷劫/心魔另结算并预告风险。
- 大突破材料、冷却、伤势和回退查表；改命三候选先保存再等待选择，刷新不重抽。
- 伤害：`max(0, floor(技能威力 × 境界成长倍率 × 境界差压制 × 元素系数 × 进攻状态系数 - 防御))`；防御动作另减伤50%。
- 克制1.3、被克0.8、中性1；跨一大境向上攻击0.4一次，跨两境默认0，例外必须具名配置。
- 命中候选：`clamp(80 + 2 × 遁速差, 5, 95)%`；同境逃跑候选：`clamp(50 + 3 × 遁速差 + 手段加成, 5, 95)%`，境界差另修正。
- 五行灵气与人物灵力分开；候选每轮3点、上限10、吸取使下轮额外+2、离战清空。绝技准备2轮可打断。

### 7.4 经济与寿元样例

候选初值：气血/灵力100、灵石100、功德/业力/声望/贡献0、炼气初期修为0、心境50。商贾额外300灵石；猎户气血上限与初始当前值均+20。

聚气丹20、筑基丹500；宗门月任务净收入候选20～40；回收价候选买价50%。不能因余额不足自动借贷，不能无成本买卖套利。

21岁炼气剩余79年；同龄筑基基础寿元上限替换为200年，剩余179年。耗月行动先处理获准的边界前行动，再增龄检查寿尽；开始时剩余0不能行动。

### 7.5 平衡不能全部推到最后

同时测两条时间轴：游戏内到达境界的年龄，以及现实中的点击数、阅读负担、单次游玩收获。

19.5月增、每阶100，四阶单纯积累约24个月；闭关更快。这不是“3～10年炼气”已达成的证据。首次模拟在 TASK-08，收入循环在 TASK-14，MVP整体在 TASK-17，高境界在 TASK-25/27。

优先调整公开阈值、资源来源、事件收益和授权快进；不靠隐藏概率、现实等待或数百次重复点击凑年限。目标冲突须记录裁决。

## 8. 技术架构与发行原则

### 8.1 与语言无关的模块边界

| 模块 | 职责 | 不得承担 |
|---|---|---|
| CLI/TUI | 启动、终端输入、布局、退出恢复 | 自行计算修为或修改存档 |
| Session | 命令路由、状态机、确认、幂等、事务 | 随意改写规则 |
| Engine | 修炼、时钟、战斗、因果、NPC、事件 | 终端控制、文件I/O、网络 |
| Content | 境界、物品、NPC、任务、文本、规则配置 | 任意可执行脚本 |
| PanelModel | 只读展示协议 | 第二套权威状态 |
| Storage | 本地快照、日志、恢复、迁移、锁 | 把摘要冒充完整存档 |
| Narrative（可选） | 意图提案、已结算事实的叙事 | 直接修改数值、生死、背包 |

引擎可复用并不代表未来 Web 迁移零成本：输入、存储、发行和平台适配仍需开发。本版不为假设中的 Web 版搭建前端工程。

### 8.2 技术选型原则

TASK-03已经依据以下问题选定Go 1.26；完整候选数据和发行证据见[ADR-002](decisions/ADR-002-technology-and-packaging.md)：

- 能否生成目标平台可运行产物，玩家不用安装开发工具？
- 中文输入、键盘、resize、退出恢复与所选终端是否可靠？
- 启动、空闲CPU、内存和安装体积是否符合随手玩的场景？
- 存档原子性、确定性测试和跨版本迁移是否易于实现？
- 能否维护后续内容，而非为了“单文件”把所有逻辑塞进一个脚本？

正式工程当前没有第三方Go模块，使用同步命令循环、ANSI输出和窄Windows控制台适配边界。Python继续用于一次性原型；Node、.NET和Rust未被选用。Go单二进制不自动代表跨平台，玩家发行包仍不得临时安装依赖。

Windows 为当前优先验证平台；macOS/Linux列为候选，逐平台构建测试后才声明支持。

### 8.3 持久化方案

替换旧稿 IndexedDB 方案，采用本地文件/嵌入式存储。TASK-03选择版本化原子JSON快照作为首选候选，TASK-06通过故障注入后正式定案；SQLite保留为回退方案：

- SQLite事务：快照、日志和幂等结果同一事务。
- 版本化快照：将所需一致状态写到同目录临时文件，刷新并原子替换，保留上一份有效快照；快照中包含对应日志尾和幂等记录，不能拆成若干互不原子的写入。

二者都必须做故障注入测试，不能仅以“写了临时文件”宣称断电安全。锁、刷盘和原子替换语义需在实际平台验证。

存档使用用户数据目录，不写入当前工作仓库或只读安装目录。具体路径由选定平台规范和实现决定，并提供“显示存档位置/导出/恢复”入口。主题、颜色档、静音和已支持的输入选项独立保存；设置损坏回退安全默认，不破坏进度。

跨版本迁移必须保留未决事件、战斗阶段、已扣材料和随机候选的语义。内容ID删除或规则变化须有显式映射；无法保真迁移时拒绝载入并保留原档，提示使用原版本继续，不静默结束战斗或重新抽奖。

每个存档单写者；第二个游戏进程只读或明确拒绝。进程崩溃后的残留锁有安全恢复流程，不能随意删锁覆盖活跃进程。

## 9. 命令、状态和确定性协议

### 9.1 核心对象

- `GameState`：schema/rules/content版本、gameId、branchId、revision、phase、三计数、rngStreams、player、world、pendingEvent、activeMonthAction、combat、retreatPlan、questStates、logCursor。
- `Player`：身份、年龄月数、寿元加成、出身/道途/灵根/体质/天赋、基础/成长属性、修正、hp/mp/xp、境界小阶、背包/装备、余额/债务、因果/声望/贡献、宗门、心境/伤势、关系、熟练度/悟道。
- `NPC`：稳定ID、年龄/寿元/境界、阵营、性格、位置、日程、目标、生死、已见事实。
- `EventDefinition`：资格、优先级、冷却、过期、权重、选择、检定、白名单效果、后续节点、风险、限次规则。
- `SaveEnvelope`：完整状态、待决选择、随机状态、已消费事件/动作、版本、日志尾、完整性校验；不含凭据。
- `PanelModel`：标题/年月/场景、紧凑状态、可展开详情、事件文本、选项、风险、变化、保存状态；布局尺寸由渲染端处理。

### 9.2 提交流程

`Command = actionId + sessionId + expectedRevision + viewToken + kind + targetId + targetInstanceId? + payload + confirmationToken?`

1. 校验进程写锁、动作ID和revision，重复动作返回既有结果。
2. 判断查询/耗月行动/事件回应/战斗/管理命令。
3. 检查前置条件和风险确认，未确认不扣材料、不抽结果骰。
4. 冻结计划，在候选状态与随机状态副本上执行。
5. 按行动成本结算月边界和事件队列；嵌套战斗不重复扣月。
6. 检查不变量，将状态、随机游标、日志和幂等结果一致提交。
7. 成功落盘才标为已保存；最后生成模板或AI叙事和面板。

AI或渲染失败不能重新执行已提交动作。再次进入可恢复上一次结果。

一次耗月历练遇战斗时，保存 `activeMonthAction` 和 `settlementPending`；战斗轮独立保存，结束后只结算原行动的一次月成本。死亡按终局协议关闭未完成行动，不能恢复后再发一次奖励。

### 9.3 随机与审计

世界事件、战斗、掉落、NPC各自独立随机流，保存算法版本、状态、计数器。日志记录判定ID、概率、结果、理由、actionId。

同快照、同版本、同动作序列得到同机械状态哈希；叙事文案可不同。运行环境变化、规则升级与浮点误差不得悄悄改变旧回放含义。

### 9.4 必须保持的不变量

- hp/mp在有效上限内；xp、余额、物品数量非负；负债独立记录。
- 同actionId不重复消费、不重复推进、不重掷。
- 查询、缩窗、帮助和空输入不改变机械状态或随机流。
- 未确认的重大决定不生效；未选突破不自动升阶。
- 死亡后禁止世界行动；已死NPC不接受礼物或新对话。
- 游戏月只由时钟推进；现实经过时间不改年龄。
- UI显示源自已提交状态；保存失败不得伪报成功。
- 读档、轮回和升级均有明确边界，不带来重复奖励漏洞。

## 10. 可选 AI 增强

M1用模板完整游玩，M2再提供独立可关闭的增强。本地安装不必然等于完全不联网，但任何远程请求必须经用户启用；默认无模型请求、无遥测、不扫描用户其他应用的凭据。

- 意图解析器只输出结构化 `ActionProposal`，限制合法动作、目标、参数和置信度。
- 叙事器只读已提交结果和可见事实，输出短文；不能改变数值或补造救援。
- 歧义输入澄清，不默认转成攻击；无法建模的行动提出可执行替代。
- 密钥不得进入存档、调试日志、内容包或命令行历史；凭据方案单独设计。
- 明示将发送哪些游戏数据；不上传工作代码、工作进程日志和无关本机路径。
- 限时、限重试、限并发、限额度；按actionId缓存；超时立即模板降级。
- 优先评估进程内适配器，不为了接模型强建本地HTTP服务。若确有需要，只绑定127.0.0.1并校验访问来源、会话令牌和请求边界。
- 不要求玩家等模型写完长文才退出，也不要求启动游戏时加载本地模型。

## 11. 质量和发行门槛

### 11.1 自动测试

- 规则：创角边界、19.5/39/29.25基线、定点累计、突破回退、寿元最后一月、伤势、境界压制、成年/同意资格。
- 可靠性：保存中断、磁盘满、权限失败、损坏档、未来版本、重复进程、残留锁、恢复未决战斗。
- 终端：标准/窄尺寸、高度分页、无空格中文、长姓名、组合字符、颜色回退、终端控制字符注入、resize不结算。
- 随机：至少100条固定种子回放逐事件哈希一致；概率规则抽样与固定用例分开。
- 概率建议：20%基础检定10万次、误差不超过0.5个百分点；仅检查纯概率，不代替事件资格和平衡测试。

### 11.2 真机和干净环境

Windows Terminal、VS Code集成终端及拟声明支持的传统控制台分别验证；未测平台标记未测。记录字体、主题、尺寸、版本和测试结果。

必须在没有开发环境的测试用户环境完成安装、启动、退出、恢复、导出、升级。不能用开发机上已有Python/Node证明玩家开箱可玩。

### 11.3 M1最低放行条件

- 无网络和API密钥即可创角、成长、交易、战斗、筑基、死亡并读档。
- 用户在任意待选节点离开，再次启动能继续；没有离线惩罚。
- 至少一个短循环能在少量选择后产生有意义进展。
- 安装后启动不下载依赖；退出恢复终端；空闲资源占用有测量。
- 无严重存档丢失、重复扣费、状态越界、随机重掷或关键选项截断缺陷。
- 内容与实际范围一致；未实现功能不伪装可用。

## 12. 首次游玩与短时会话

本节把“等程序出结果时玩一下”落实为可制作的流程。以下操作、数值和内容是本版设计基线；体验时长是验证目标，不是倒计时或已经取得的成绩。

### 12.1 第一次启动

无存档时进入“新建角色”，第一页显示作者署名。默认选中一个合法预设，玩家可改姓名、道号和性别；选择“详细设定”才展开两步完整创角。预设也须经过相同60点校验，不给隐藏属性优势。创角确认前不推进月份，确认后立即保存初始状态。

M1快速入口提供三种偏好：均衡修炼、稳健生存、灵活探索。默认21岁；具体出身、灵根、天赋及效果由版本化配置列出，未实现的天赋不放进预设。不同预设均能通过散修路径取得突破材料。快速创角目标为3次以内确认，不把逐字输入姓名计算为选择次数。

进入洞府后只给一个近期目标：“积累修为，准备第一次小突破”。完整世界观、十境列表和所有系统介绍移到帮助。引导可跳过、可重看，不能通过反复查看领取奖励。

### 12.2 一次两分钟会话

| 步骤 | 玩家看到的内容 | 操作与可见反馈 |
|---|---|---|
| 恢复 | 上次停在洞府，正在准备小突破 | 一句话摘要；无待决事件则直接进入场景 |
| 第一次选择 | 修炼一月、委托、坊市、历练 | 修炼立即显示修为增加和本次耗时 |
| 分支 | 若触发奇遇，显示短文、代价和2～4项选择 | 可以选择，也可以退出并保留此节点 |
| 目标反馈 | 距离当前目标还差多少修为或材料 | 不自动突破，不弹长篇剧情 |
| 回到工作 | `q 退出`与明确保存状态 | 正常退出回到原命令提示符，下次继续 |

玩家只完成一次修炼就退出也算有效会话。产品不把“玩满五分钟”“完成一场战斗”或“看完一次剧情”设为保存条件。

M1筑基成功后提供本阶段回顾和“继续在青岳游历／读取存档／另建角色”。可以继续现有生活循环，但筑基后续成长标注“本版未开放”，不显示一个永远无法完成的突破目标，也不冒充飞升结局。

### 12.4 选择的成本必须看得见

行动预览至少显示游戏耗时、必付资源和已知危险。只在突破、致命风险、放弃重要任务、覆盖手动档等场景额外确认。概率使用引擎实际输入计算；无法准确估计的战斗不伪造胜率，使用境界差和明确危险描述。

不把轻松等同于永远成功。普通收入任务提供低风险路径；探索和越级挑衅可以失败甚至死亡，但不得在未提示的新手安全行动里突然抽出必死事件。

## 13. M1行动与状态规格

### 13.1 时间成本矩阵

| 行为 | 世界月成本 | 是否推进战斗轮 | 规则 |
|---|---:|---|---|
| 查看、帮助、翻页、设置、退出 | 0 | 否 | 不抽领域随机数 |
| 创角确认、接取／领取委托、入宗确认 | 0 | 否 | 可改变状态并保存；限次奖励只领一次 |
| 修炼、疗伤、显式等待 | 1 | 否 | 完成行动后结算一个月 |
| 洞府、宗门、坊市之间本地移动 | 0 | 否 | 固定安全节点，不以往返刷新收益 |
| 买卖及非战斗用药 | 0 | 否 | 数量、价格与消耗有账；用药效果不能靠重进界面重触发 |
| 执行一次委托、外出历练 | 1 | 遭遇战时独立推进 | 整段父行动只扣一个月，奖励按实例只结算一次 |
| 小突破、大突破尝试 | 1 | 劫难节点不算世界月 | 拒绝或取消准备为0；开始后成功、失败均耗月 |
| 事件选择、雷劫、心魔、改命选择 | 0额外月 | 否 | 使用父行动时间；额外耗月选项须显式另建行动 |
| 战斗攻击、防御、观察、用药、逃跑 | 0额外月 | 是 | 一次提交涵盖本轮必要的双方结算 |
| 战斗敌情查看、取消技能选择 | 0 | 否 | 与会消耗一轮的“观察破绽”分开命名 |

M1不开放多月批处理闭关，普通修炼按月选择；闭关倍率与长期逐月计划在TASK-23接入。TASK-08可提前验证闭关公式，不能因此把批处理入口标为已实现。

### 13.2 月份边界与事件顺序

1. 检查角色尚可行动，验证成本、前置条件和必要确认。
2. 创建唯一父行动，记录待结算月成本；只扣一次启动材料。
3. 执行即时效果或进入遭遇／劫难子状态。存在子状态时不能再开始另一个耗月行动。
4. 子状态结束后结算父行动结果；活着的角色先应用成功突破等即时寿元变化，再增加一个月年龄、扣减本月持续状态期限并处理月末效果。
5. 检查死亡／寿尽；已终局不再抽下一事件。其他情况下处理任务到期、必发事件与基础奇遇检定，保存已产生的待决节点。
6. 原子保存后显示结果，等待下一输入。月末事件的零额外月选择不再次触发月末。

战斗中死亡则记载终局发生于该行动月内，关闭父行动，不再推进活人世界、不发成功奖励。月末寿尽则本月已推进一次。两种情形均清空待扣月标记；恢复不得再次结算。

### 13.3 会话状态与输入保护

| 状态 | 允许的领域操作 | 离开与恢复 |
|---|---|---|
| CREATION | 编辑并确认角色 | 保存草稿；恢复后仍需确认建档 |
| READY | 场景行动、交易、查看 | 恢复最近场景与变化摘要 |
| CONFIRMING | 确认当前提案或取消 | 仅UI暂态；退出作取消，未扣材料，下次重新预览 |
| EVENT_PENDING | 当前事件选项 | 恢复同一事件实例和候选集 |
| COMBAT_PENDING | 当前轮合法战斗行动 | 恢复同一轮，等待玩家，不免费追加敌方攻击 |
| BREAKTHROUGH_PENDING | 当前雷劫、心魔或改命选择 | 保留已扣材料、已完成节点和候选，不重抽 |
| SAVE_ERROR | 重试保存、查看错误、退出 | 不继续领域行动；提示磁盘中最后确认版本 |
| ENDED | 查看回顾、读档或另建角色 | 终局可恢复；不接受修炼等世界行动 |

查询、帮助、退出在所有等待输入的状态均可用；存储提交中的退出请求延迟至一次提交结束或失败，不能把半个行动显示为成功。SAVE_ERROR退出须明确告知未保存候选会丢弃，不能无声退出。

防连按不能只靠actionId。每次选择同时绑定`viewToken`与当前待决实例，提交期间停收领域输入，切换界面后丢弃旧按键队列；新的面板等待新的按下动作。确认、选择和纯文本输入分别路由：姓名输入中的q就是字母，不能触发退出；粘贴多行不能自动执行一串选择。

### 13.4 随机失败与读档的边界

“不重抽”指相同存档状态、相同规则与相同行动序列得到同样结果，关闭重开、翻页和重复提交不能刷新候选。玩家主动读取更早检查点后改走另一条行动路线，结果可以不同。单机普通模式不设计联网反作弊或禁止玩家备份存档的机制。

十二个事件节点是不同的可执行选择节点，不以同文案换名字凑数，也不要求一次会话全部遇见。下表是候选内容规格，不等于已有配置；具体收益在TASK-04/11/14填齐并校验。

| 节点ID | 场景与目的 | 选择产生的区别 |

| EVT-002 | 坊市委托告示 | 接安全杂务、查看采药、暂不接取 |
| EVT-003 | 采药岔路 | 取普通草药或冒已提示风险深入 |

NPC候选采用原稿顾清玄、云栖及一位明确成年的原创委托人；原创资料须标记“新增设定”。M1只制作交易、任务、切磋和简短对话；完整恋爱、双修和NPC自主生态留在后续任务。

所有事件至少包含稳定ID、父行动、触发条件、显示文本、选项成本、效果、风险、可重复性、冷却和后继节点。必需资源不能只由一次可永久错过的奇遇发放；关键事件拒绝后要有放弃说明或替代路径。

### 14.1 收入与成长算例

安全杂务候选：每次消耗一个游戏月，净得30灵石，不含随机奖励；初始100灵石。若不额外消费，为500灵石筑基丹补足400，需要`ceil(400 / 30) = 14`次，余额520，购丹后余20。实际杂务执行每次均推进月份并接受月末调度；零月接取和领取不能直接重复刷钱。

基准修炼19.5、每阶100、满额截断且突破不结转溢出时，每阶需6次修炼。炼气四阶共24次修炼；三次小突破和一次大突破首试均成功时再耗4个月。收入与修炼不重叠的上述简化路径合计42个月，包含14次杂务；失败、疗伤及额外消费会增加成本。该算例解释约3.5年如何形成，不把结果当成平衡实测或所有角色的保证。

首轮平衡应记录“42个耗月行动之外又有多少菜单操作”。接取／交付过多时优先优化快捷入口和清楚的下一步，不通过隐藏免费资源篡改账单，也不急于添加自动挂机。

## 15. 启动与本地使用约定

暂定程序名`wendao`，仅为待实现的CLI接口，不表示现在可以运行。Windows首发候选为便携压缩包，解压后在独立终端运行`.\wendao.exe`；加入PATH后可使用`wendao`。安装器和全局PATH修改不是首版必需条件。

| 入口 | 预期行为 |
|---|---|
| `wendao` | 恢复上次角色；无档时创角；损坏档进入恢复说明 |
| `wendao new` | 新建独立角色槽，不覆盖已有角色 |
| `wendao saves` | 列出本机角色与检查点，不推进时间 |
| `wendao --no-color` | 无色模式；仍保留明确危险标签 |
| `wendao --help` / `--version` | 纯文本信息，非TTY可用 |

Windows建议数据根目录为`%LOCALAPPDATA%\WendaoChangsheng\`，下分配置、角色存档、备份和滚动诊断日志。实际路径由实现解析，缺失或不可写时明确报错，不回退写入用户工作仓库。日志建议单文件1MB、轮转3份；自动恢复点保留当前与上一份有效状态，高风险检查点建议保留最近5份，手动命名档不自动删除。具体SQLite或快照布局由技术试验定案。

普通启动只访问自身安装内容与数据目录，不扫描当前项目、不连接工作程序、不后台联网检查更新。升级为玩家手动替换发行包：启动新版前保留旧包和旧档，迁移失败保持原档可用。卸载程序不会静默删掉进度；删除角色在游戏内二次确认，明确指出目标角色。
