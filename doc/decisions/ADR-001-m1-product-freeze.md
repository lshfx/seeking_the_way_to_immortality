# ADR 001 M1 产品范围与规则冻结

- 状态：已采纳，适用于M1
- 日期：2026-09-22
- 关联任务：TASK-01
- 依据：项目根目录 1.txt、用户明确的本地终端摸鱼游戏定位、设计文档v0.3
- 权限说明：只有标为“用户确认”的方向来自用户直接表述。其余是为使首版可开发而采纳的M1项目决定；它们不声称是用户逐条指定的要求。

## 1. 产品承诺

《问道长生》首版是一款本机运行、独自游玩的终端修仙小游戏。玩家在另一个终端会话里玩几次短回合，工作程序继续运行；离开或关闭游戏不让角色衰老。首次交付须断网可从创角玩到筑基，存档写在本机，不需要账户。

用户已确认“打工人的摸鱼游戏”“只安装到本地”“等待程序出结果时可打开终端玩一会儿”。下表其余决定是本次TASK-01为落地首版所采纳的基线。

| 决定 | M1基线 | 边界 |
|---|---|---|
| 产品形态 | 单机CLI/TUI；用键盘菜单和短文本游玩 | 不做浏览器、图形窗口、联网账户、联机或游戏内广告 |
| 首个目标平台 | Windows x64便携发行包 | 只有完成真实终端和干净环境验收后才声明支持；其他平台以后验证 |
| 离线与隐私 | M1功能完整离线；无遥测、无自动更新、无AI请求 | 任何未来联网功能独立选择加入，不读取工作日志、代码、凭据或其他进程 |
| 工作隔离 | 用户在另一个终端标签页或窗口自行启动与切换 | 不监控工作进程、不接管工作终端输入输出、不伪装进程或发通知 |
| 短时节奏 | 单次行动短、完成一项选择就能安全退出；1～5分钟会话为测试目标 | 不要求玩满时间，不设签到、倒计时或离开惩罚 |
| 画面 | TUI为正式首版界面，取代强制LaTeX排版；紧凑状态区、当前事件和有限选项 | 键盘优先；真彩、基础色和无色模式由TASK-02验证；不保证所有终端字体 |
| 发行与存档 | 单写者、本机用户数据目录、每次已提交进展有恢复记录 | 安装目录不存档；升级前备份；卸载不静默删除角色 |

“本地安装”“完全离线”“独立终端启动”是三个不同约束。本决定把M1核心定为完全离线；未来可选扩展不得改变离线核心。

## 2. M1完成范围

玩家可快速使用合法预设开始，也可细调姓名、道号、性别、年龄、出身、灵根、体质、六维和天赋。创角第一屏署名“作者：雾见川”。初期内容包含青岳洞府、青云宗、天机坊市和一个低危历练地点；至少三位有固定事实资料的NPC、十二个有不同结果的事件节点，以及“问道飞升”和“守护所爱”两条早期目标。两个目标均可通过散修路径推进，不以入宗、恋爱或AI为通关前提。

唯一的首版大境界突破道路为**人道筑基**。M1完整走通炼气小阶、材料准备、主动确认、雷劫与心魔节点、成功或失败以及后续恢复，目标为筑基初期。地道、天道的内容ID或配置可以预留，但不能在菜单里显示为可用。M1之外的成长入口须写明“本版尚未开放”；达到阶段终点有回顾，仍可在已开放青岳场景游玩。

M1不制作恋爱、双修或性内容。关系系统留待后续任务；届时继续执行年龄明确、双方成年、自愿和不按玩家性别限制关系的约束。M1可以写非恋爱友谊和互助。

### 2.1 初期数值边界

这些数值用于首版配置和可复现验收，不等于高境界平衡已经完成。

| 项目 | 冻结值 |
|---|---|
| 创角年龄 | 16～60周岁；M1推荐预设21岁 |
| 六维分配 | 基础共60点，每项1～15；应用出身和天赋后最终每项1～20，越界必须要求玩家重配 |
| 验收角色资源 | 气血100、灵力100、灵石100；其他出身加值逐项显示并计入账本 |
| 炼气境界 | 初、中、后、圆满四阶；每阶阈值100点，满额不自动突破，超额修为不跨阶结转 |
| 基准月修为 | 有效资质10、真灵根、黄阶功法、普通环境、达标心境时，普通修炼19.5点；定点内部累计，显示才舍入 |
| 小突破失败 | 修为回到本阶阈值的70%；成功进入新阶段后修为归零 |
| M1大突破路线 | 人道筑基。启动成功率基线95%；启动只代表进入后续劫难，不代表筑基必成 |
| 基础奇遇 | 每个存活且结算完毕的耗月行动完成后进行一次20%基础检定；不合资格时不重掷 |
| 经济校验 | 聚气丹20灵石、筑基丹500灵石、安全杂务每次净收入30；初始100灵石时需14次杂务补足买丹差额 |
| 年龄和寿元 | 按整数月保存；21岁炼气角色的基础炼气寿元为100年，耗月后按月更新 |

成长公式、初值与账目以设计文档第7节及第14.1节为准。基准算例是自动化夹具，不保证任何灵根、伤势、随机分支或玩家选择下都能在同样时长筑基。筑基劫的最终通关率由启动判定、明确的雷劫和心魔规则共同决定，TASK-16不得把95%宣传成总成功率。

## 3. 时间、提交和死亡规则

沿用interactionSeq、worldMonth与combatRound三个独立计数。

- 查询、帮助、换页、空输入、取消确认、进出安全菜单、退出和切换窗口耗时均为零，不推进随机流。
- 一次修炼、疗伤、显式等待、委托执行或历练行动耗一个游戏月。拒绝或取消尚未开始的行动不耗月；开始后失败仍承担已预告的月成本。
- 行动中的遭遇战、雷劫和心魔是同一父行动的子状态，不额外扣月。一次战斗提交原子结算本轮双方的必要结果；玩家不输入时敌人不会自动行动。
- 完成耗月行动后，只进行一次月末结算：应用存活结果、增加一个月年龄、到期效果和月末规则，再做基础奇遇检定。死亡或寿尽时不抽下一随机事件，不发成功奖励。精确顺序见设计文档第13.2节。
- M1不提供批量闭关入口。闭关增长倍率可作为规则单测，逐月计划与NPC长期模拟留给TASK-23。
- 每次成功提交领域行动、产生随机候选或推进一个战斗/劫难阶段时保存可恢复状态。强杀时恢复最近一份完整已提交状态；保存失败不显示成功，且停止接受会改变世界的行动。
- 死亡是当前角色分支的终点。先显示死因，再由玩家选择读取最近有效检查点并建立新分支，或新建角色；保留死亡记录。不在死亡时静默自动回滚或假装角色复活。没有有效检查点时如实告知。
- 游戏不读取现实经过时间。离线、切换窗口、系统休眠、电脑关机和系统时钟调整都不推进角色、NPC、利息、种植或寿元。

## 5. M1验收门槛

TASK-01把产品与规则范围冻结；不代表功能已实现。M1发布仍须通过：

1. 断网、无账户、无API密钥完成创角、修炼、交易、任务、战斗、筑基和死亡检查点恢复。
2. 进入、退出和恢复不推进现实时间；一个行动只有一个actionId、一次账目和一次月末结算。
3. 开始危险行动前显示已知风险与必付资源；中途退出恢复同一待决节点。
4. 散修与宗门两条早期目标皆能抵达筑基准备；不出现只有一次且可能永久错失的必需突破材料。
5. 工作目录无写权限时仍可将存档写入用户数据目录；第二进程不能并写；存档失败不伪报成功。
6. TUI的风险文本与选择在目标尺寸可访问；尺寸、真彩/基础色/无色支持以TASK-02的实测结果为准。
7. 筑基阶段完成后说明可继续的区域和未开放内容；不显示假的高境入口。

## 7. 变更流程

M1实现、配置、测试与说明以本ADR及其引用的v0.4设计、开发文档为同一基线。若测试发现目标无法达成，记录问题与备选方案，更新本决策记录和受影响任务的验收后再改规则。不得只改宣传语，也不得用实现细节悄悄改掉时间、死亡或隐私边界。
