# TASK-14 宗门任务与散修收入 — 验证记录

- **状态：** 已完成实现与自动化验证（2026-09-27）。
- **依赖：** TASK-10 月末调度、TASK-11 场景与NPC、TASK-12 资源/伤势、TASK-13 背包与坊市。
- **定位：** 为本地终端摸鱼游戏提供一次操作就有反馈的稳定收入路径，同时保留不入宗的散修路线。接取、领取是零月操作；执行委托明确耗时一月。

## 已交付

任务生命周期现在由引擎维护在 `World.Quests`：`offered → accepted → complete/failed → claimed`。接取会检查任务宣告、NPC是否在当前场景、宗门门槛和所需物品；所需物品在接取时一次性预留并从背包扣除，存档记录预留清单。执行只允许在配置地点进行，消耗一个游戏月；失败结果写入任务状态，不能进入成功领取分支。成功奖励只能领取一次，领取后重复提交会被拒绝。

M1目录提供六类可见委托：坊市杂务、采药、护送药材、青云试行、宗内巡逻和同门切磋。杂务为无随机失败的散修基础收入，每月净得30灵石；采药和护送会显示配置的失败概率，巡逻和切磋要求已经入宗。新增加入青云宗前置的“青云试行”任务，完成并领取后才能确认入宗；入宗不会自动发生，也不会推进游戏月。

宗门身份使用既有 `Player.SectID`，贡献和声望继续使用统一资源账本。巡逻成功领取时额外结算青云宗配置的20灵石月任务收入，贡献奖励与灵石收入分别记账。主界面新增 `4` 查看委托，委托详情提供接取、执行确认、领取和入宗动作；`5` 在青云宗场景办理入宗。确认页会显示执行地点、耗时和失败概率。

## 经济与路径核算

设计基线为初始100灵石、杂务每次净得30、筑基丹价格500。补足400灵石需要 `ceil(400 / 30) = 14` 次杂务，执行14个月后余额520，购丹后余20。接取和领取不改变游戏月，也不能绕过执行直接获得奖励；零月菜单操作不会触发月末事件或宗门收入。

宗门路径的最小操作顺序是：到青云宗 → 接取并执行青云试行（一月）→ 领取10贡献 → 确认入宗 → 接取并执行巡逻（一月）→ 领取20贡献和20灵石月任务收入。散修可以一直执行坊市杂务，不需要 `SectID`，也不需要先完成宗门任务。

## 存档、随机与迁移

SchemaVersion 从5升至 **6**，RulesVersion 从6升至 **7**，ContentVersion 从6升至 **7**。摘要新增宗门身份、任务状态、进度、接受/完成月份、冷却月份和预留物品；旧 TASK-13（5/6/6）存档会先保留原始字节，再创建空任务表并升级到当前版本，不能凭空猜测一项任务已完成。任务失败概率使用持久化世界随机流；0‰和1000‰不消耗随机数，中间概率只抽一次，结果会随任务状态保存。

任务状态校验拒绝未知状态、负时间、超范围进度、状态与领取标记不一致、重复预留物品和缺失内容引用。宗门入口任务不得反过来要求宗门身份，避免出现无法完成的循环依赖。

## 当前边界

失败委托不会自动退还接取时已预留的材料；这是本轮明确的风险成本。任务奖励目前只使用白名单资源/物品授予接口，复杂对话、战斗遭遇、筑基丹消耗和突破结果分别由 TASK-15/16 接入。坊市仍是固定价有限库存，不做自动补货、拍卖、借贷或行情波动。Windows Terminal 等正式程序的人工兼容矩阵仍待补测。
